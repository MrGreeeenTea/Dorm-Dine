## Problem Statement

Should users be required to create an account and log in before they can browse available meals, or should they be allowed to explore food offers first and only be required to log in when they want to place an order?
Our web application is designed to help students discover affordable home-cooked meals within their dormitory.
As a new platform, attracting users and encouraging engagement is one of our primary goals. Requiring registration too early in the user journey may create unnecessary friction and cause potential users to leave before they experience the value of the platform.
At the same time, ordering food requires user identification to ensure trust, accountability, and communication between buyers and sellers.

## Decision

We allow users to browse available meals without logging in.
Users can explore meal offers, view descriptions, prices, and availability before creating an account. However, once a user decides to place an order, they will be required to register and log in.
This approach reduces the entry barrier for new users while still ensuring that all transactions take place between authenticated members of the platform.
By allowing users to see the available food first, we increase the likelihood that they recognize the value of the platform before being asked to create an account.

## Regarded options

We regarded two alternative options:

+ Require Login at the start
+ Require Login before placing order

| Criterion | Require login before browsing | Allow browsing before login |
| --- | --- | --- |
| **User onboardinge** | ❌ Higher entry barrier | ✔️ Easy and immediate access |
| **User experience** | ❌ User may leave before seeing value | ✔️ User can discover meals first |❔
| **Data security** | ✔️ Only registered users see content | ❔ Browsing content is public |
| **Trust during transaction** | ✔️ Authenticated from the start | ✔️ Authentication required before ordering |
| **User acquisition** | ❌ Registration may discourage new users | ✔️ More likely to attract new users |
| **Implementation effort** | ✔️ Simpler access control | ❔ Additional checks before ordering |
