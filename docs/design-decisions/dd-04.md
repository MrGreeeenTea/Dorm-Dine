## Problem Statement

The dashboard is supposed to be a summary of the app. 
It houses multiple elements that need to be arranged in favor of relevance.
The user is supposed to immediatly have the information most important available to them.

The current state is unfinished as the dashboard misses functions for the user to edit and delete created dishes.

## Decision

The order of the elements was not chosen at random. Instead I intentionally moved the "Wohnheim selection" to the very top since it is the deciding factor of where someone sees the available offers.
It is most important the user can decide what location they want to use. Since if I were to put it at the bottom they would have to scroll through offers in a Wohnheim they might not be at right now.
Underneath that I moved "My orders" since it is the next most relevant data to the user. Opening the app, and immediatly seeing the status of an order is most beneficial for the user.
My Dishes was moved unter that because it is only relevant to users with the role "is_cook". But since they can order and sell meals this was the most logical choice.
At the very bottom at the currently available offers. At the moment we dont have many examples but in the future i want to display only so many offers, and instead have the user go to the page for the available offers to browse more. 

*Decision was taken by:* github.com/meismara (Luisa Razny)

## Regarded options

We regarded multiple alternative options:

+ Have Wohnheim selection("changes") only available in Profile page("settings")
+ Have My Dishes only visible in the Profile page + changes to those only available there
+ Place current available offers at the very top for more engagement

| Criterion | Profile only actions | Feed(current available offers) at the top | chosen arrangement
| --- | --- | --- | --- |
| **User Friction** | ❌ adds annoying page reloads and extra navigation | ✔️ quick acces to buying food - what the user got the app for | ✔️ quick access to relevant information |
| **Data Context** | ✔️ splits user related fuctions from basic dashboard overview | ❌ stupid to put feed above Wohnheim selection | ✔️ changes feed in accordance with chosen Wohnheim, blends user related fuctions with user interests |
| **Easy Roles** | ✔️ Hides Role based elements without issue | ❔ irrelevant because feed visibility is unaffected by roles | ✔️ uses access control for relevance for user |
