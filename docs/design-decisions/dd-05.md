# 05: Should we define all models in one file or split them into separate files?

## Meta

Status
: Work in progress - **Decided** - Obsolete

Updated
: 13-June-2026

## Problem Statement

As the application grows, the number of SQLAlchemy models increases. We need to decide whether to keep all models together in a single `db.py` file, or split them into a `models/` folder with one file per model (e.g. `user.py`, `dish.py`).


## Decision

We will use a `models/` folder with one file per model.

Splitting models into separate files makes it easier for team members to see which models exist and quickly find the one relevant to their work, without having to scroll through a single large file. It also keeps the codebase more organized and easier to navigate overall.


*Decision was taken by:* github.com/A-Ye311 (Angelina Ye)

## Regarded options

We regarded two alternative options:

+ `db.py`
+ `models/`


| Criterion | Single db.py | One file per model 
| --- | --- | --- |
| **Readability** | ❌ File becomes long and harder to navigate as models grow | ✔️ Each model is isolated and easy to find |
| **Scalability** | ❌ Gets messy with many models | ✔️ Scales cleanly, one file per concern |
| **Imports** | ✔️ Single import location | ❔ Slightly more imports, but more explicit |
| **Convention** | ❔ Common for small projects | ✔️ Common for larger Flask/SQLAlchemy projects |
