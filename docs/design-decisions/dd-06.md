# 06: Should we define the routes in a separate file or put them in app.py?


## Meta

Status
: Work in progress - **Decided** - Obsolete

Updated
: 21-June-2026

## Problem Statement

As the application grows, the number of Flask routes increases. We need to decide whether to keep all routes in a single file, or split them into a `routes/` folder with one file per resource (e.g. `user_routes.py`, `dish_routes.py`).

## Decision

We will keep all routes in `app.py` for now, instead of splitting them into a `routes/` folder.

Splitting routes by resource would reduce merge conflicts and improve readability as the app grows. However, `app.py` has already grown large with a lot of interconnected logic, and migrating all existing routes into separate files would require significant effort right now without an immediate, pressing problem to justify it. We will revisit this decision if `app.py` keeps growing or if merge conflicts become a frequent, recurring issue.

*Decision was taken by:* github.com/A-Ye311 (Angelina Ye)

## Regarded options

We regarded two alternative options:

+ `routes/`
+ `app.py`

| Criterion | Single app.py | One file per resource
| --- | --- | --- | --- |
| **Merge conflicts** | ❌ Everyone editing the same file, frequent conflicts | ✔️ Each resource can be edited independently |
| **Readability** | ❌ File becomes long and harder to navigate as routes grow | ✔️ Each resource's routes are isolated and easy to find |
| **Scalability** | ❌ Gets messy with many endpoints | ✔️ Scales cleanly, one file per resource |
| **Convention** | ❔ Common for small projects | ✔️ Common for larger Flask projects, matches Blueprint pattern |
| **Migration effort** | ✔️ No extra work needed, already in place | ❌ Requires reworking all existing routes, high effort at this stage |
