# 03: Dashboard Template Refactoring

## Meta

Status
: Work in progress - **Decided** - Obsolete

Updated
: 18-Jun-2026

## Problem Statement

The first dashboard build relied heavily on the grid layout system of bootstrang and its components, pre build usibility classes as well as external rendering utilities. 
During full-stack integration (specifically while trying to connec Flask-Login session data in favor of working out how certain user roles intract with and view the dashboard) I was met with constant Errors. 
Because of the volume of the design code i was uncertain if the issue was with the HTML-design or my written logic. I was getting frustrated with being unable to find the Issue. 
Checking back with my team I realized people worked with simpler HTML as well, so this influenced my design to fully rework the user dashboard for effeciency and concistency reasons.   

## Decision

In favor of aligning with what my Teammates were doing or planning to do I reworked the HTML to fit a way simpler design. 
The Error messages have reduced and it is way easier for me to make adjustments now.
If we want to make the design more appealing later one it can be build on the basic structure we currently use. 

*Decision was taken by:* github.com/meismara (Luisa Razny)

## Regarded options

We regarded two alternative options:

+ Keep the bootstrang heavy dashboard in favor of looks
+ Change it to make the dashbaord more effecient, consistent with existing design and easier to work with overall

| Criterion | First build | Simpler HTML Layout |
| --- | --- | --- |
| **Bug Isolation** | ❌ Hard to tell where the issue was | ✔️ easier to navigate; more visibility |
| **Routing Control** | ❌ A pain | ✔️ Standard url_for() |
| **Dev Speed** | ✔️ Fast setup because pre build styling | ❌ build structrues before styling |
| **Implementation Effort** | ❌ Constant errors and conflicts | ❔ focus on if it's working and it is for now |
