# 03: Should we use Flask-WTF or make forms manually with with HTML

## Meta

Status
: Work in progress - **Decided** - Obsolete

Updated
: 12-June-2026

## Problem Statement

For our project we need a form for at least three parts of our web application. The user registration, login and meal creation.
We were evaluating if we should implement forms manually using HTML or use the Flask-WTF extension which is build on WTForms.

## Decision

We decided to implement Flask-WTF for all forms in our project. 
Additionally WTForms integrates well with Flask and SQLAlchemy. The resources Mr. Eck provided convinced us that using the WTForms is the right decision for our project.

*Decision was taken by:* github.com/juliadhwr

## Regarded options

We regarded two options:

+ Continue without the Extension using HTML
+ With WTForms

| Criterion | Without WTForms | With WTForms|
| --- | --- | --- |
| **Efficiency** | ❌ each form would require manual html and route handling | ✔️ Forms are defined as Python classes (easier to modify) |
| **Convinience** | ❌ Validators would be written manually for each field increasing risks of potential bugs | ✔️ Validators are included |
| **Data security** | ❌ Would have costed extra efforts to provide form security (CSRF) through manual implementation | ✔️ Automatically includes CSRF tokens |
| **Compatibility** | ✔️ No difference | ✔️ Flask supports the integration of the Extension and form data integrates with SQL Alchemy |
